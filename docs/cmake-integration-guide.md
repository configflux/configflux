# CMake and Build System Integration Guide

This guide shows how to consume ConfigFlux export artifacts from CMake and
non-CMake build systems. It covers the three generated files produced by the
`cpp_early_binding_v1` export profile, the recommended CMake variable
conventions, a CI shell script example, and a Makefile snippet for projects
that do not use CMake.

**Prerequisites:** You have already compiled a CMP package with
`configflux-compiler compile` and run the full interpreter pipeline
(open, select, resolve, export-resolved) as described in
`docs/canonical-worked-example.md`.

## Generated Artifacts

The `export-resolved` interpreter command with profile `cpp_early_binding_v1`
produces three files under the `generated/` prefix in its output:

| File | Purpose |
|---|---|
| `generated/config.hpp` | C++ header with `inline constexpr` values in `configflux::buildcfg` namespace |
| `generated/config_build_flags.cmake` | CMake snippet that sets variables and compile definitions |
| `generated/config_artifact_manifest.json` | JSON manifest listing bound artifacts and their paths |

These files are deterministic: the same resolve hash always produces
identical file contents.

### config.hpp

The generated header declares one constant per construction-lifecycle
parameter. Constants live in the `configflux::buildcfg` namespace and use
`inline constexpr` so they are available at compile time with no linker
overhead.

Example (from the S1 water pump scenario):

```cpp
#pragma once

namespace configflux::buildcfg {
inline constexpr const char* kThermalControlControlDriver = "hydra_x200_dual_driver";
}  // namespace configflux::buildcfg
```

Example (from the S4 mobile robot scenario, showing multiple bindings):

```cpp
#pragma once

namespace configflux::buildcfg {
inline constexpr const char* kBatteryManagerBatteryProfile = "high_density";
inline constexpr const char* kDriveStackDriveDriver = "mecanum_drive_driver";
inline constexpr const char* kDriveStackDriveProfile = "mecanum";
inline constexpr const char* kLocalizationStackLocalizationDriver = "lidar_localization_driver";
inline constexpr const char* kPayloadStackPayloadDriver = "payload_heavy_driver";
}  // namespace configflux::buildcfg
```

Symbol naming convention:
- Header symbols use UpperCamelCase with a `k` prefix: `k<Component><Param>`
- The component ID and parameter key are concatenated and normalized
  (e.g., `thermal_control` + `control_driver` becomes `kThermalControlControlDriver`)

### config_build_flags.cmake

The generated CMake file sets one CMake variable per construction-lifecycle
parameter and adds compile definitions for preprocessor-based variant
selection.

Example (from the S4 mobile robot scenario):

```cmake
# Generated by ConfigFlux profile cpp_early_binding_v1
set(CFG_BATTERY_MANAGER_BATTERY_PROFILE "high_density")
set(CFG_DRIVE_STACK_DRIVE_DRIVER "mecanum_drive_driver")
set(CFG_DRIVE_STACK_DRIVE_PROFILE "mecanum")
set(CFG_LOCALIZATION_STACK_LOCALIZATION_DRIVER "lidar_localization_driver")
set(CFG_PAYLOAD_STACK_PAYLOAD_DRIVER "payload_heavy_driver")
add_compile_definitions(
  CFG_BATTERY_MANAGER_BATTERY_PROFILE_HIGH_DENSITY=1
  CFG_DRIVE_STACK_DRIVE_DRIVER_MECANUM_DRIVE_DRIVER=1
  CFG_DRIVE_STACK_DRIVE_PROFILE_MECANUM=1
  CFG_LOCALIZATION_STACK_LOCALIZATION_DRIVER_LIDAR_LOCALIZATION_DRIVER=1
  CFG_PAYLOAD_STACK_PAYLOAD_DRIVER_PAYLOAD_HEAVY_DRIVER=1
)
```

Variable naming convention:
- CMake variables use UPPER_SNAKE_CASE with a `CFG_` prefix: `CFG_<COMPONENT>_<PARAM>`
- Compile definitions append the value in UPPER_SNAKE_CASE: `CFG_<COMPONENT>_<PARAM>_<VALUE>=1`

This allows C/C++ code to use `#ifdef` or `#if` guards for variant selection:

```cpp
#if CFG_DRIVE_STACK_DRIVE_DRIVER_MECANUM_DRIVE_DRIVER
  // Mecanum-specific initialization
#endif
```

### config_artifact_manifest.json

The artifact manifest records which artifacts were bound during resolution
and which component parameter paths reference them.

Example (from the S1 water pump scenario):

```json
{
  "artifacts": [
    {
      "artifact_id": "hydra_x200_dual_driver",
      "bound_paths": [
        "component.thermal_control.param.control_driver"
      ]
    }
  ],
  "model_hash": "<model_hash>",
  "profile": "cpp_early_binding_v1",
  "resolve_hash": "<resolve_hash>",
  "schema_version": 4
}
```

## CMake Integration

### Recommended CMake Variables

Define two variables in your CMake project to locate the ConfigFlux export
artifacts:

| Variable | Description |
|---|---|
| `CONFIGFLUX_STORE_ROOT` | Root directory of the ConfigFlux artifact store |
| `CONFIGFLUX_RESOLVE_HASH` | Resolve hash identifying which resolved configuration to use |

These variables construct the path to the generated files in the artifact
store layout:

```
<CONFIGFLUX_STORE_ROOT>/
  products/
    <product_family_id>/
      resolved/
        <CONFIGFLUX_RESOLVE_HASH>/
          config.hpp
          config_artifact_manifest.json
          config_build_flags.cmake
```

### Minimal CMakeLists.txt Example

```cmake
cmake_minimum_required(VERSION 3.16)
project(my_firmware)

# --- ConfigFlux integration ---

# These can be set via -D flags, environment variables, or a preset file.
# Example: cmake -DCONFIGFLUX_STORE_ROOT=/opt/cfx-store
#                -DCONFIGFLUX_RESOLVE_HASH=abc123...
#                -DCONFIGFLUX_PRODUCT_FAMILY=water_pump
if(NOT CONFIGFLUX_STORE_ROOT)
  message(FATAL_ERROR "CONFIGFLUX_STORE_ROOT must be set")
endif()
if(NOT CONFIGFLUX_RESOLVE_HASH)
  message(FATAL_ERROR "CONFIGFLUX_RESOLVE_HASH must be set")
endif()
if(NOT CONFIGFLUX_PRODUCT_FAMILY)
  message(FATAL_ERROR "CONFIGFLUX_PRODUCT_FAMILY must be set")
endif()

set(CFX_RESOLVED_DIR
  "${CONFIGFLUX_STORE_ROOT}/products/${CONFIGFLUX_PRODUCT_FAMILY}/resolved/${CONFIGFLUX_RESOLVE_HASH}")

# Include the generated CMake build flags.
# This sets CFG_* variables and adds compile definitions.
include("${CFX_RESOLVED_DIR}/config_build_flags.cmake")

# --- Your project targets ---

add_executable(firmware src/main.cpp)

# Add the resolved directory to the include path so that
# #include "config.hpp" finds the generated header.
target_include_directories(firmware PRIVATE "${CFX_RESOLVED_DIR}")

# The compile definitions from config_build_flags.cmake are already
# added globally via add_compile_definitions(). If you prefer
# target-scoped definitions, replace the add_compile_definitions()
# call in config_build_flags.cmake with target_compile_definitions().
```

### Using the Generated Header in C++ Source

```cpp
#include "config.hpp"

void init_driver() {
    const char* driver = configflux::buildcfg::kThermalControlControlDriver;
    // Use the resolved driver identifier at compile time.
    start_driver(driver);
}
```

### Using Compile Definitions for Preprocessor Guards

```cpp
#include "config.hpp"

void init_subsystem() {
#if CFG_THERMAL_CONTROL_CONTROL_DRIVER_HYDRA_X200_DUAL_DRIVER
    init_hydra_x200_dual();
#else
    init_generic_driver();
#endif
}
```

### Direct Path Approach (Without Store Variables)

If your project does not use the artifact store layout, you can point
directly at the export output directory:

```cmake
# Point directly at the directory containing the export artifacts.
set(CFX_EXPORT_DIR "${CMAKE_SOURCE_DIR}/configflux-export")

include("${CFX_EXPORT_DIR}/config_build_flags.cmake")

add_executable(firmware src/main.cpp)
target_include_directories(firmware PRIVATE "${CFX_EXPORT_DIR}")
```

## CI Shell Script Example

The following script runs the full ConfigFlux pipeline as a pre-build step
in CI, then invokes CMake with the resolved artifact paths.

```bash
#!/usr/bin/env bash
set -euo pipefail

# --- Configuration (set by CI environment or passed as arguments) ---
STORE_ROOT="${CONFIGFLUX_STORE_ROOT:?Set CONFIGFLUX_STORE_ROOT}"
PRODUCT_FAMILY="${CONFIGFLUX_PRODUCT_FAMILY:?Set CONFIGFLUX_PRODUCT_FAMILY}"
SCOPE="${CONFIGFLUX_SCOPE:-component:thermal_control}"
SOURCE_DIR="${CONFIGFLUX_SOURCE_DIR:?Set CONFIGFLUX_SOURCE_DIR to the directory containing CUE-exported .json source chunks}"

# Path to ConfigFlux binaries (adjust to your installation)
COMPILER="${CONFIGFLUX_COMPILER:-configflux-compiler}"
INTERPRETER="${CONFIGFLUX_INTERPRETER:-configflux-interpreter}"

WORK_DIR="$(mktemp -d)"
trap 'rm -rf "${WORK_DIR}"' EXIT

# --- Step 1: Compile the source model ---
SOURCES=()
for f in "${SOURCE_DIR}"/*.json; do
  SOURCES+=(--source "$f")
done

"${COMPILER}" compile "${SOURCES[@]}" --out "${WORK_DIR}/cmp" \
  > "${WORK_DIR}/compile.result.json"

STATUS=$(jq -r '.status' "${WORK_DIR}/compile.result.json")
if [ "${STATUS}" != "ok" ]; then
  echo "ERROR: compile failed with status ${STATUS}" >&2
  jq '.diagnostics' "${WORK_DIR}/compile.result.json" >&2
  exit 1
fi

# --- Step 2: Open the CMP with the interpreter ---
jq -n --arg cmp "${WORK_DIR}/cmp/cmp.manifest.json" \
  '{schema_version: 4, cmp_manifest_ref: $cmp}' \
  > "${WORK_DIR}/open.request.json"

"${INTERPRETER}" open \
  --request-file "${WORK_DIR}/open.request.json" \
  --response-file "${WORK_DIR}/open.result.json"

# --- Step 3: Initialize selection state ---
jq -n \
  --slurpfile open "${WORK_DIR}/open.result.json" \
  --arg scope "${SCOPE}" \
  '{
    schema_version: 4,
    model_handle: $open[0].model_handle,
    scope: $scope,
    context_tags: {}
  }' \
  > "${WORK_DIR}/init-selection-state.request.json"

"${INTERPRETER}" init-selection-state \
  --request-file "${WORK_DIR}/init-selection-state.request.json" \
  --response-file "${WORK_DIR}/init-selection-state.result.json"

SELECTION_STATE="${WORK_DIR}/init-selection-state.result.json"

# --- Step 4: Apply selections (project-specific) ---
# For each facet/option pair, call the interpreter select command.
# Example for S1 water pump scenario:
#
#   for DELTA in '{"facet":"cooling_brand","option":"hydra"}' \
#                '{"facet":"cooling_model","option":"x200"}' \
#                '{"facet":"pump_type","option":"dual"}'; do
#     jq -n \
#       --slurpfile open "${WORK_DIR}/open.result.json" \
#       --slurpfile state <(jq '.selection_state' "${SELECTION_STATE}") \
#       --argjson delta "${DELTA}" \
#       --arg scope "${SCOPE}" \
#       '{
#         schema_version: 4,
#         model_handle: $open[0].model_handle,
#         scope: $scope,
#         selection_state: $state[0],
#         selection_delta: $delta
#       }' > "${WORK_DIR}/select.request.json"
#
#     "${INTERPRETER}" select \
#       --request-file "${WORK_DIR}/select.request.json" \
#       --response-file "${WORK_DIR}/select.result.json"
#
#     SELECTION_STATE="${WORK_DIR}/select.result.json"
#   done

# --- Step 5: Resolve ---
jq -n \
  --slurpfile open "${WORK_DIR}/open.result.json" \
  --slurpfile state <(jq '.selection_state' "${SELECTION_STATE}") \
  --arg scope "${SCOPE}" \
  '{
    schema_version: 4,
    model_handle: $open[0].model_handle,
    scope: $scope,
    selection_state: $state[0]
  }' \
  > "${WORK_DIR}/resolve.request.json"

"${INTERPRETER}" resolve \
  --request-file "${WORK_DIR}/resolve.request.json" \
  --response-file "${WORK_DIR}/resolve.result.json"

RESOLVE_HASH=$(jq -r '.resolve_hash' "${WORK_DIR}/resolve.result.json")
echo "Resolve hash: ${RESOLVE_HASH}"

# --- Step 6: Export early-binding artifacts ---
jq -n \
  --slurpfile rr "${WORK_DIR}/resolve.result.json" \
  '{
    schema_version: 4,
    resolve_result: $rr[0],
    profile: "cpp_early_binding_v1"
  }' \
  > "${WORK_DIR}/export-resolved.request.json"

"${INTERPRETER}" export-resolved \
  --request-file "${WORK_DIR}/export-resolved.request.json" \
  --response-file "${WORK_DIR}/export-resolved.result.json"

# --- Step 7: Write export artifacts to the artifact store ---
RESOLVED_DIR="${STORE_ROOT}/products/${PRODUCT_FAMILY}/resolved/${RESOLVE_HASH}"
mkdir -p "${RESOLVED_DIR}"

# Extract generated files from the export result and write them to the store.
jq -r '.generated_artifacts.files[] | "\(.path)\t\(.contents)"' \
  "${WORK_DIR}/export-resolved.result.json" | \
while IFS=$'\t' read -r path contents; do
  FILENAME=$(basename "${path}")
  printf '%s' "${contents}" > "${RESOLVED_DIR}/${FILENAME}"
done

echo "Export artifacts written to: ${RESOLVED_DIR}"
echo "  config.hpp"
echo "  config_build_flags.cmake"
echo "  config_artifact_manifest.json"

# --- Step 8: Invoke CMake build ---
cmake -B build \
  -DCONFIGFLUX_STORE_ROOT="${STORE_ROOT}" \
  -DCONFIGFLUX_RESOLVE_HASH="${RESOLVE_HASH}" \
  -DCONFIGFLUX_PRODUCT_FAMILY="${PRODUCT_FAMILY}"

cmake --build build
```

## Makefile Snippet for Non-CMake Projects

For projects that use Make or another non-CMake build system, consume the
export artifacts directly.

```makefile
# --- ConfigFlux integration ---
# Set these variables in your environment or at the top of your Makefile.
CONFIGFLUX_STORE_ROOT ?= /opt/cfx-store
CONFIGFLUX_PRODUCT_FAMILY ?= water_pump
CONFIGFLUX_RESOLVE_HASH ?= $(error Set CONFIGFLUX_RESOLVE_HASH)

CFX_RESOLVED_DIR := $(CONFIGFLUX_STORE_ROOT)/products/$(CONFIGFLUX_PRODUCT_FAMILY)/resolved/$(CONFIGFLUX_RESOLVE_HASH)

# Add the resolved directory to the include path for config.hpp
CXXFLAGS += -I$(CFX_RESOLVED_DIR)

# Parse compile definitions from config_build_flags.cmake.
# The cmake file uses add_compile_definitions(DEF1=1 DEF2=1 ...).
# Extract definitions and convert to -D flags.
CFX_CMAKE_FILE := $(CFX_RESOLVED_DIR)/config_build_flags.cmake
CFX_DEFS := $(shell grep -oP '(?<=  )\S+=\S+' $(CFX_CMAKE_FILE) 2>/dev/null | sed 's/^/-D/')

CXXFLAGS += $(CFX_DEFS)

# --- Your project ---
CXX ?= g++
SOURCES := src/main.cpp
TARGET := firmware

$(TARGET): $(SOURCES)
	$(CXX) $(CXXFLAGS) -o $@ $^

.PHONY: clean
clean:
	rm -f $(TARGET)
```

### How the Makefile Parses config_build_flags.cmake

The `config_build_flags.cmake` file has a predictable structure:

1. `set(VAR "value")` lines define CMake variables (not directly usable by Make)
2. `add_compile_definitions(...)` block lists preprocessor definitions

The Makefile snippet above extracts definitions from the
`add_compile_definitions()` block using grep and converts them to `-D` flags.
If you also need the `set()` variable values (for example, to pass a driver
name as a build argument), parse them with:

```makefile
# Extract set(CFG_THERMAL_CONTROL_CONTROL_DRIVER "hydra_x200_dual_driver")
# into a Make variable.
CFG_THERMAL_CONTROL_CONTROL_DRIVER := $(shell grep 'set(CFG_THERMAL_CONTROL_CONTROL_DRIVER' $(CFX_CMAKE_FILE) | grep -oP '"\K[^"]+')
```

## Troubleshooting

### "CONFIGFLUX_STORE_ROOT must be set"

Set the variable when invoking CMake:

```bash
cmake -DCONFIGFLUX_STORE_ROOT=/path/to/store ...
```

Or export it in your shell before running your build:

```bash
export CONFIGFLUX_STORE_ROOT=/path/to/store
```

### config_build_flags.cmake not found

Verify that the `export-resolved` step completed successfully and that the
resolve hash matches the directory name in the artifact store:

```bash
ls "${CONFIGFLUX_STORE_ROOT}/products/${PRODUCT_FAMILY}/resolved/${RESOLVE_HASH}/"
```

### Compile definitions not taking effect

Ensure your CMakeLists.txt calls `include()` for `config_build_flags.cmake`
**before** defining your targets. The `add_compile_definitions()` in the
generated file applies globally to all targets defined after the `include()`.

### config.hpp not found during compilation

Add the resolved directory to your include path:

```cmake
target_include_directories(my_target PRIVATE "${CFX_RESOLVED_DIR}")
```

For non-CMake builds, pass `-I<resolved_dir>` to the compiler.
